# Food Planner Telegram Bot

Telegram-приложение для личного и совместного недельного рациона. Python 3.12+, aiogram 3, async SQLAlchemy 2, SQLite, Alembic и openpyxl. Работает через long polling: входящие порты, домен и HTTPS-сертификат не нужны.

## Быстрый запуск — CasaOS

1. Скопируйте `food-planner-bot.zip` в `/DATA/AppData`.
2. Выполните в терминале сервера:

```bash
cd /DATA/AppData
unzip food-planner-bot.zip -d food-planner-bot
cd /DATA/AppData/food-planner-bot
cp .env.example .env
nano .env
```

3. Вставьте настоящий `BOT_TOKEN`, при необходимости задайте `ADMIN_IDS`.
4. В nano: **Ctrl+O**, **Enter** — сохранить; **Ctrl+X** — выйти.
5. Подготовьте каталоги и запустите:

```bash
mkdir -p data logs
sudo chown -R 10001:10001 data logs
chmod 600 .env
docker compose up -d --build
docker compose logs -f
```

6. Откройте бота в Telegram, отправьте `/start`, затем выберите демо, мастер настройки или импорт Excel. Мастер не обязателен.

## Bot Token и администраторы

Откройте в Telegram **@BotFather**, отправьте `/newbot`, задайте имя и username бота. Полученный токен вставьте в `.env`:

```dotenv
BOT_TOKEN=123456789:YOUR_SECRET_FROM_BOTFATHER
ADMIN_IDS=123456789,987654321
```

Значения здесь — примеры. Реального токена в проекте и ZIP нет. Telegram ID своего аккаунта можно посмотреть в `/settings` после первого запуска. Впишите этот ID в `ADMIN_IDS` и примените изменённый ENV:

```bash
docker compose up -d --force-recreate
```

`docker compose restart` не перечитывает изменённые переменные окружения. `ADMIN_IDS` отделены от роли OWNER: владелец управляет одним пространством, администратор сервера имеет доступ к полной резервной копии всех пользователей.

При отсутствии токена запуск завершается сообщением:

```text
BOT_TOKEN is missing. Configure .env before starting the bot.
```

## CASAOS / LINUX INSTALLATION

Проверьте установленный Docker:

```bash
docker --version
docker compose version
```

CasaOS обычно уже использует Docker. Не устанавливайте поверх него второй Docker. Если `docker compose` отсутствует, проверьте способ установки CasaOS и установите Compose plugin, совместимый с существующим Docker. Для систем с уже подключённым официальным Docker APT-репозиторием пакет называется `docker-compose-plugin`.

Если отсутствует unzip:

```bash
sudo apt update
sudo apt install unzip -y
```

Распаковка и проверка файлов:

```bash
cd /DATA/AppData
unzip food-planner-bot.zip -d food-planner-bot
cd /DATA/AppData/food-planner-bot
ls -la
cp .env.example .env
nano .env
mkdir -p data logs
sudo chown -R 10001:10001 data logs
chmod 600 .env
```

Контейнер работает с UID/GID `10001:10001`. Каталоги должны быть доступны этому пользователю. Только `data` и `logs` требуют записи; корневая файловая система контейнера доступна только для чтения.

В `.env.example` заданы пути **внутри контейнера**:

```dotenv
DATABASE_URL=sqlite+aiosqlite:////app/data/database/food_planner.db
DATA_DIR=/app/data
TIMEZONE=Europe/Berlin
BACKUP_ENABLED=true
BACKUP_RETENTION_DAILY=7
BACKUP_RETENTION_WEEKLY=4
```

Постоянные данные на сервере:

- `/DATA/AppData/food-planner-bot/data/database/food_planner.db`
- `/DATA/AppData/food-planner-bot/data/backups/`
- `/DATA/AppData/food-planner-bot/logs/app.jsonl`

Запуск и управление:

```bash
docker compose config --quiet
docker compose build
docker compose up -d
docker compose ps
docker compose logs -f
```

`Ctrl+C` при просмотре логов закрывает просмотр, не останавливает контейнер.

```bash
docker compose restart
docker compose down
```

`restart: unless-stopped` возвращает бот после перезагрузки Docker/сервера, если его не останавливали вручную. При запуске entrypoint сначала проверяет конфигурацию, затем применяет `alembic upgrade head`; при ошибке миграции бот не запускается. SIGTERM/SIGINT корректно останавливают polling и scheduler, закрывают Bot session и подключения БД.

### CasaOS Custom App

Основной путь — команды Compose выше. Контейнер может отображаться в CasaOS как обычный Docker container.

Для Custom App сначала соберите образ `food-planner-bot:local` через `docker compose build`. Укажите этот образ, UID/GID `10001:10001`, restart policy `unless-stopped`, переменные из `.env` и два bind mount: абсолютный серверный `data` → `/app/data`, `logs` → `/app/logs`. Порты не добавляйте. Если импортируете Compose через интерфейс CasaOS, преобразуйте относительные host-пути в абсолютные пути данного проекта. Не запускайте одновременно экземпляры через GUI и terminal с одним токеном.

Нижнее меню в два столбца: Сегодня, Неделя, Покупки, Блюда, Питание, Напоминания, Совместный рацион, Настройки. Вложенные действия — inline-кнопки; длинные списки имеют пагинацию.

- Дневной и недельный рацион, карточки блюд, инструкции и ингредиенты.
- Калории и БЖУ рассчитываются по ингредиентам, порциям и личным количествам.
- Изменение общего рецепта создаёт версию и сразу влияет на будущие чтения всех участников.
- Можно заменить блюдо, изменить количество продукта, добавить продукт с пищевой ценностью и изменить инструкцию.
- Несколько меню в пространстве, переключение активного, переименование, удаление и восстановление версии.
- Личные отметки еды по пользователю, блюду и календарной дате; повторное нажатие снимает отметку.
- Вес, история измерений, целевой вес, цели питания.
- Личные уведомления еды/готовки, покупок сегодня/завтра/недели и недельного плана.
- Совместные пространства, одноразовые приглашения с ограниченным сроком, роли и отзыв приглашений.
- Общий checklist покупок и ручные товары; состав покупок всегда рассчитывается из актуального меню.
- Excel-шаблон, демо, экспорт, валидация, preview, сравнение, подтверждение и история импорта.
- Admin: пользователи, пространства, статистика, импорты, последние ошибки, backup и рассылка с preview/подтверждением.

Команды зарегистрированы через Bot API: `/start`, `/menu`, `/today`, `/tomorrow`, `/week`, `/shopping`, `/shopping_today`, `/shopping_tomorrow`, `/shopping_week`, `/meals`, `/nutrition`, `/weight`, `/reminders`, `/import`, `/export`, `/template`, `/household`, `/invite`, `/settings`, `/help`, `/backup`, `/admin`. `/cancel` отменяет незавершённый ввод.

## Расчёты и покупки

Общий рецепт содержит количества **на весь рецепт**, `servings` — число порций рецепта. Количество участника: `amount × portion / servings`. Явное личное количество продукта заменяет результат масштабирования только для данного участника и недельного приёма.

Например, у Denys 220 г курицы, у Anna 150 г: общие покупки содержат 370 г. Отключённый личный тип приёма исключается из личного рациона, общей суммы его порций и уведомлений.

Внутренние единицы: `g`, `ml`, `pcs`. `kg` и `l` конвертируются при импорте. Пищевая ценность **всегда на 100 canonical units**: 100 г, 100 мл или 100 штук, независимо от единицы количества в Excel. Для яиц в демо используется масса в граммах. Пересчёт массы в объём без плотности не выполняется.

Один `ingredient_id` означает один и тот же продукт с одинаковыми единицами и БЖУ во всех рецептах данной версии. Его количества агрегируются. Ручные товары хранятся отдельно с источником `manual`, автоматически вычисленные имеют источник `menu`.

Отметки покупки общие **в рамках выбранного периода**: список конкретного дня и список недели имеют отдельные отметки. При изменении суммарного количества или единицы отметка товара сбрасывается при чтении, чтобы не показывать старое количество купленным. Старые кнопки проверяют идентичность и количество товара перед изменением.

Меню повторяется по дням недели. Порции также привязаны к недельному слоту. Вес и съеденные блюда сохраняются с конкретными датами. Исторические отметки еды привязаны к исходной версии и не переносятся автоматически на заменённые блюда; при откате исходной версии снова видны её отметки.

## Excel ↔ ChatGPT ↔ Telegram

1. `/template` — чистый шаблон; `/export` — активное меню.
2. Отправьте `.xlsx` в ChatGPT.
3. В боте откройте Настройки → Excel / ChatGPT → Промт.
4. Скопируйте текст, добавьте задачу: например, «Сделай завтраки быстрее и рацион около 2800 kcal».
5. Получите изменённый `.xlsx` с прежней структурой.
6. `/import` → отправьте файл → изучите preview, предупреждения и сравнение.
7. Подтвердите: новая версия, отдельное меню или замена активной версии. Замена сохраняет предыдущую версию для отката.

Листы: `README`, `MENU`, `RECIPES`, `INGREDIENTS`, `SETTINGS`, `NOTIFICATIONS`. Названия колонок перечислены в шаблоне. `MENU.menu_id=0`, `menu_version=0` допускаются для нового шаблона. В одном файле — одно меню. При импорте экспортированного чужого меню выбирайте «Отдельное меню».

`MENU` содержит справочные kcal/protein/fat/carbs: бот заново рассчитывает их из рецептов и предупреждает о расхождениях. `SETTINGS` и `NOTIFICATIONS` применяются **только к импортирующему пользователю**, не к остальным участникам. Персональные порции, отметки еды/покупок и история веса не входят в экспорт общего меню.

`NOTIFICATIONS.weekday` — дополнительная необязательная колонка: 0=Пн … 6=Вс, по умолчанию 5=Сб. Для еды/готовки используется каждый день с подходящим блюдом. Другие типы приёмов поддерживаются через новые значения `meal_type` в Excel; список типов в интерфейсе расширяется автоматически.

Файл ограничен `MAX_IMPORT_MB` (по умолчанию 5 МБ), распакованное содержимое — 30 МБ, число строк/колонок ограничено. Формулы, макросы, внешние ссылки запрещены. На экспорт строки записываются как текстовые ячейки, включая строки с `=`, `+`, `-`, `@`.

До подтверждения рацион, версии, рецепты и настройки не меняются. Preview существует в памяти 30 минут. Перезапуск сбрасывает незавершённый ввод и preview — загрузите файл ещё раз. Подтверждение проверяет права и актуальность меню, затем создаёт все связанные записи одной транзакцией. Ошибка откатывает транзакцию.

Готовые файлы также находятся в `app/templates/excel/`. Они генерируются командой `python -m scripts.generate_templates`.

## Общий рацион

1. Пользователь A: `/household` → Создать → название.
2. `/invite` выдаёт ссылку. **Отправьте её пользователю B самостоятельно.**
3. B открывает ссылку и подтверждает вступление. Роль по умолчанию — VIEWER.
4. A: Участники → роль → EDITOR, если B должен редактировать.
5. A импортирует меню. B открывает Сегодня/Неделя/Покупки и видит актуальные данные без импорта.
6. Для своих количеств: карточка блюда → Моя порция или Мои граммы.

Каждый пользователь может состоять в нескольких пространствах и переключаться между ними. Уведомления используют его текущее активное пространство. Уже отправленное Telegram-сообщение является снимком: откройте раздел заново, чтобы увидеть чужие изменения. Старые карточки изменённого меню не позволяют редактировать неактуальную версию.

| Право | OWNER | EDITOR | VIEWER |
|---|---|---|---|
| Смотреть меню/рецепты/покупки | да | да | да |
| Менять общий рацион/рецепты | да | да | нет |
| Отмечать общие покупки | да | да | нет |
| Импортировать | да | если разрешил OWNER | нет |
| Отмечать свою еду | да | да | если разрешил OWNER |
| Настраивать свои порции, вес, уведомления | да | да | да |
| Приглашения, роли, исключение, удаление | да | нет | нет |

Владелец не может выйти, оставив пространство без владельца; доступно удаление с подтверждением. Удаление пространства удаляет его меню/версии, но сохраняет личный профиль и вес пользователей. У активных участников создаётся личное пространство. Полный backup доступен только `ADMIN_IDS`.

## Напоминания и reboot

Центральный async scheduler опрашивает сохранённые правила каждые 20 секунд. Отдельные бесконечные задания на пользователей не создаются. Очередь доставки и ключи дедупликации находятся в SQLite.

В `/reminders` выберите тип и приём, день недели (для недельных), время `HH:MM`, для готовки — сколько минут заранее. Часовой пояс IANA индивидуален, по умолчанию `Europe/Berlin`. Кнопка «Через 15 мин» сохраняет отложенную доставку; «Готово» отменяет её.

После reboot восстанавливаются настройки и сохранённая очередь. Пропущенные события собираются за последние 5 минут, чтобы не посылать все старые напоминания разом. Обычные напоминания старше 2 часов не отправляются. При переводе часов несуществующее локальное время пропускается, повторяющееся срабатывает один раз.

Telegram rate limits обрабатываются через RetryAfter, временные ошибки повторяются до 5 попыток. Заблокировавшие бота получатели не останавливают очередь. При аварии ровно между отправкой Telegram и записью результата возможен повтор доставки: Telegram sendMessage не предоставляет ключей идемпотентности. Запускайте **один процесс/контейнер** на токен и SQLite БД.

Healthcheck проверяет свежесть heartbeat после успешного прохода scheduler и БД. Это проверка жизнеспособности процесса, а не гарантия доступности Telegram. Docker сам не перезапускает просто `unhealthy` контейнер; смотрите логи и состояние сети.

## Backup и восстановление

Автоматически раз в UTC-день создаётся согласованная копия через SQLite Backup API; WAL не копируется побайтово. Выполняется `PRAGMA integrity_check`, файл записывается атомарно и получает права 0600. Хранятся 7 последних дневных и 4 недельных копии (настраивается в ENV).

Администратор: `/backup` создаёт копию и отправляет файл в личный Telegram-чат. Можно создать её без Telegram:

```bash
docker compose exec bot python -c 'from app.config import Settings; from app.services.backup import create_backup; print(create_backup(Settings()))'
ls -lah data/backups
```

Для восстановления выберите конкретный файл. Сначала остановите бот и сохраните текущую БД вместе с WAL/SHM в отдельную папку:

```bash
cd /DATA/AppData/food-planner-bot
docker compose down
sudo mv data/database data/database-before-restore
mkdir -p data/database
sudo cp data/backups/daily-YYYY-MM-DD-HHMMSS-ffffff.sqlite3 data/database/food_planner.db
sudo chown -R 10001:10001 data/database
docker compose up -d
docker compose logs --tail=100
```

Замените имя backup на существующее. Если `database-before-restore` уже существует, выберите новое имя. Не подмешивайте старые `-wal`/`-shm` к восстановленной БД. Храните дополнительную копию backup вне диска домашнего сервера.

## Обновление

Сделайте `/backup`. Обновите исходники из нового ZIP, сохранив `.env`, `data/`, `logs/`:

```bash
cd /DATA/AppData/food-planner-bot
docker compose down
unzip -o /DATA/AppData/food-planner-bot.zip -d /DATA/AppData/food-planner-bot
docker compose build --no-cache
docker compose up -d
docker compose logs -f
```

Архив не содержит `.env` и пользовательских данных. Миграции применяются при старте. Для отката к старому коду после несовместимых миграций используйте подходящую резервную копию БД.

## Разработка и проверки

Python 3.12 или новее. Для локального запуска пути отличаются от Docker:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock -r requirements-dev.txt
cp .env.example .env
nano .env
```

В локальном `.env` установите:

```dotenv
DATABASE_URL=sqlite+aiosqlite:///data/database/food_planner.db
DATA_DIR=data
```

Затем:

```bash
.venv/bin/alembic upgrade head
.venv/bin/alembic check
.venv/bin/python main.py --check
.venv/bin/pytest -q
.venv/bin/ruff check app tests scripts main.py
.venv/bin/python -m compileall -q app main.py
.venv/bin/python main.py
```

`--check` проверяет импорты, конфигурацию путей и мигрированную БД без сетевого подключения и без токена. Обычный запуск требует настоящий токен. CI проверяет Python 3.12, тесты, миграции и сборку Docker. Фактический запуск CI требует размещения репозитория на GitHub.

Тесты покрывают БЖУ/единицы, общий список и личные количества, два независимых пользователя, роли, просроченные/повторные приглашения, Excel и formula injection, dry-run/transaction rollback, версии, устаревшие карточки, timezone/DST, очередь доставки, backup, экраны и обработчики кнопок.

## Структура и расширение

```text
app/
  bot/
    handlers/actions.py    # команды, кнопки, мастер, подтверждения и ввод
    handlers/screens.py    # экраны с пагинацией
    commands.py            # регистрация slash-команд
    middleware.py          # авторизация пользователя, транзакции, ошибки
    ui.py                  # Reply/Inline и типизированный CallbackData
  database/models.py       # нормализованные SQLAlchemy entities
  database/session.py      # async engine, SQLite WAL/FK/busy_timeout
  services/domain.py       # Pydantic-контракты и чистые расчёты
  services/planner.py      # права, версии, household, порции, покупки
  services/excel.py        # безопасный Excel import/export/preview
  services/backup.py       # online SQLite backup и retention
  scheduler/worker.py      # расписание и durable outbox
  seed/demo.py             # 7 дней, примерно 2500–2600 kcal
  templates/excel/         # чистый шаблон и демо
  config.py
  logging_config.py
migrations/                # явная начальная Alembic-миграция
scripts/                   # entrypoint, healthcheck, ZIP, шаблоны
tests/
data/                      # только runtime, не поставляется с БД
logs/
main.py
Dockerfile
docker-compose.yml
```

ORM хранит User → Household/Member → Menu → MenuVersion → Meal → Recipe → RecipeIngredient → Ingredient. День представлен полем `Meal.day`, а не отдельной таблицей без дополнительных данных. Персональные `MealAssignment`, `MealCompletion`, WeightLog, Notification отделены от общих данных. Настройки пользователя — JSON-словарь; повторяемые сущности — отдельные таблицы. История импорта/экспорта и изменения — Audit. Shopping не хранится статичным текстом: сохраняются только ручные товары и отметки с отпечатком количества.

Версии неизменяемые. Редактирование создаёт новую версию; CAS revision защищает от устаревшего preview. Авторизация повторяется в сервисах, а не только скрывает кнопки. Callback содержит только короткие идентификаторы, пользовательские тексты не становятся разметкой HTML.

Переход на PostgreSQL предполагает установку `asyncpg`, изменение DATABASE_URL, проверку миграций, замену backup на `pg_dump` и добавление блокировок/claim в outbox перед масштабированием на несколько воркеров. SQLite-специфичные PRAGMA изолированы в фабрике engine.

Демо содержит приблизительные значения пищевой ценности, это пример работы приложения, не медицинская рекомендация. Приложение не ставит диагнозы.


Получится `food-planner-bot.zip` без верхней вложенной папки. Скрипт использует разрешённый список исходников: в ZIP не попадают `.env`, токены, `.venv`, кеши, рабочая БД, логи, старые импорты/экспорты и backup. Пустые каталоги представлены `data/.gitkeep`, `logs/.gitkeep`.

## Проверенные границы поставки

## AI-меню

На главной странице доступно **✨ AI Меню**, также команда `/ai`.
Задайте `OPENROUTER_API_KEY` в `.env` и примените `alembic upgrade head`.
Без ключа обычные функции продолжают работать. Сначала загрузите каталог
ингредиентов через Excel или демо. AI выбирает блюда; КБЖУ рассчитывает Python
по существующему каталогу. Бюджет — пожелание, не точная стоимость.

Мастер AI переведён на ru/uk/en/de; язык выбирается в **Настройки → Язык**.
Старые экраны пока остаются русскоязычными. До подтверждения активное меню
не меняется. После сохранения используются существующие версии, порции семьи
и список покупок. Preview показывает базовую порцию, период начинается с понедельника.

Можно пересоздать всё меню, один день или одно блюдо. Неизвестные ограничения
требуют уточнения; при аллергиях проверьте состав продуктов самостоятельно.
Лимиты хранятся в SQLite, настраиваются через `AI_USER_DAILY_LIMIT` и
`AI_USER_COOLDOWN_SECONDS`. Сброс дневного лимита — 00:00 UTC.

`pytest -q` не расходует квоту OpenRouter. Live-тест не добавлен и не запускался.
Проверка вручную: `/ai` → параметры → генерация → preview → сохранение → покупки.
